# Completion blockers and provisional recommendation

## Outcome

No evaluated candidate is production-ready or eligible for finalist freeze.
The common B1 frontier contains 15 candidates and zero finalists. All currently
identified safe, affordable, high-value automated architecture hypotheses have
been executed or rejected, but the plateau rule is not satisfied because the
best accepted local candidate passes only 12 of 24 hard gates.

The provisional research leader is
`qwen2.5-0.5b-retrieval-ledger-draft-v2`: local approved-example retrieval,
a compact claims/decision ledger, and one bounded draft pass. It is the most
useful base for future work because it has the strongest accepted local hard-
gate rate (50%), 87.1981 mean development score, 2.850-second mean latency,
and zero settled cost. This is not a deployment recommendation. Do not use any
evaluated candidate for unsupervised production writing.

Higher-scoring Ox Alpha candidates are rejected for unsupported source
expansion and, in one branch, artifact contamination. The Qwen2.5 7B scale
probe scored 90.6529 but regressed to 7/24 hard gates and produced 15 material
source-expansion findings. Both genuine LoRA branches failed advancement and
memorization controls. Model scale, external ceiling quality, and synthetic
fine-tuning therefore do not supply a valid shortcut around authentic task
data and human-confirmed fidelity.

## What remains blocked

| Completion condition | Current blocker | Required authority or evidence |
| --- | --- | --- |
| Authentic unified training | No authentic rough-to-final corpus is both available and `training_approved` | User/counsel approval of a specifically documented corpus, or user-contributed rights-cleared pairs |
| Standalone source runs | No profile clears both rights and the frozen 50k-token/100-example/three-genre/30-holdout threshold | Rights promotion plus sufficient independent material for an affected profile |
| B2 aggregate shadow development | Zero B1-eligible candidates and no separately controlled true B2 operator/data | A passing candidate and quarantined aggregate-only operator |
| Tier C one-shot holdout | Zero frozen finalists and no genuinely access-separated real holdout | User-controlled or quarantined holdout and signer after finalist freeze |
| Final human confirmation | Zero hard-gate-passing finalists | A valid 3–5 candidate freeze, then intended-audience raters |
| WritingBench execution | Upstream judge is not pinned to an exact API model version | Frozen exact judge/provider/prompt/decoding configuration |
| YapBench execution | Dataset repository has no license metadata | Explicit dataset rights clarification |

Codex and Ox Alpha cannot promote unresolved data to `training_approved`,
invent hidden cases, operate both sides of the access boundary, manufacture
human ratings, or freeze immature candidates merely to advance phases.

## Safe work completed before stopping

- The full first-evidence, unified-training, source-profile coverage, external
  ceiling, structured-generation, and larger-model branches are reproducible.
- Six requested external suite IDs were acquired at exact public pins and
  adapted against real source bytes. Their 1,128 candidate-payload rows exclude
  references and checklist criteria. No model predictions or benchmark scores
  were fabricated.
- The B2/Tier C lifecycle is implemented with synthetic fixtures, aggregate-
  only receipts, access-separation attestations, one-shot enforcement, and
  retirement.
- The Tier D intended-audience protocol is implemented with blinded opaque
  labels, pseudonymous rater cohorts, publish-readiness labels, critical-error
  vetoes, edit burden, pairwise preference, agreement, and subgroup aggregates.
  No study or packet has been created because the readiness gate fails.

## Continuation trigger

The highest-value unblock is authentic task data, not another prompt or model
sweep. A useful authorization packet should identify each proposed corpus,
provenance, privacy review, license or permission evidence, approved uses,
split isolation, and the authority making the decision. After approval, the
next run must:

1. compile and contamination-scan authentic rough-to-final task pairs;
2. freeze a new unified training config and a with/without-synthetic ablation;
3. compare it against the compact-ledger leader on B1;
4. require 24/24 deterministic hard gates and a clean full-output audit;
5. only then freeze finalists and invoke B2, Tier C, and Tier D in order.

Paid training is not yet the sole remaining path because the required approved
data does not exist. No budget request or paid resource is justified until the
rights/data gate is cleared and a costed run can test a concrete candidate.
